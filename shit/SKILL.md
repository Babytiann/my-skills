# Shit：工作区代谢

只做两件事：查出问题；经用户确认后，安全清理。先报告，后动手；用户没勾选的一律不动。

| 参数 | 范围 |
|---|---|
| 无（默认） | 全部 |
| `disk` | A 磁盘 |
| `context` | B 常驻上下文 |
| `repo` | C 仓库结构 |

每个检查项的含义、处置方式和风险见 [检查项目录](references/checks.md)。

## 安全红线

| 不做 | 原因 |
|---|---|
| 未经确认就删除或修改 | 体检单只是建议 |
| 用 `rm` 删除 | 一律用 `trash`，可以从废纸篓找回 |
| 读取或打印凭据 | settings.json 里的 env、`~/.claude.json`、auth.json、.credentials.json、.env 都不读出内容；脚本只取需要的键名和数值 |
| 动正在用的东西 | 当前会话、24 小时内有写入的会话记录、`sessions/`、`session-env/`、`ide/`、`daemon/` |
| 直接删第三方管理的 skill | npx skills、cc-switch 都有自己的安装记录，直接删链接会和它们对不上；只给出管理器的命令 |
| 悄悄丢掉 eat 吸收的知识 | 可以合并、精简、挪位置，但删掉的知识点要逐条列出，仓库里的改动用 git 可以回滚 |
| 改用户的项目代码或业务数据 | 不在范围内 |

## 1. 扫描

```bash
python3 -I -B <本 skill 目录>/scripts/scan.py --days 30 --project "$PWD" [--only disk|context|repo]
```

- 用户没带参数时不加 `--only`。
- 脚本只读，只输出数字、路径和名字，不输出会话内容。
- 默认扫描 `~`；仓库取脚本解析软链后所在的 git 仓库。找不到仓库时，用 `--repo <路径>` 指定，否则跳过 C 组。
- 需要进一步计算时，加 `--format json`。

脚本末尾的「发现」带编号（A1、B3……）和检查项名，是体检单的底稿。阈值写在 `scripts/scan.py` 顶部的 `THRESHOLDS`，报告开头也会列出。

## 2. 诊断

按检查项目录解读每条发现，再补上脚本判断不了的部分（检查项目录末尾的「人工判断项」）：

- 功能重叠的 skill；
- CLAUDE.md、rules 和某个 skill 的内容重复；
- agent 读代码就能推出来的规则；
- eat 写进去但缺出处的条目。

每个判断都要指到具体的文件或 skill 名。调用次数只是下限，不能单凭「没调用」就判定没用。

## 3. 出体检单

```markdown
# 工作区体检单（<日期>）

总结：<一句话：最大的问题；能回收多少空间；能省多少常驻字数>

## A 磁盘
| # | 现状 | 问题 | 建议处置 | 收益 | 风险 |
|---|---|---|---|---|---|

## B 常驻上下文
（同上）

## C 仓库结构
（同上）

## 已检查、无需处理
- <检查项>：<为什么不用处理>
```

- 沿用脚本的编号，方便用户勾选；脚本发现之外的人工判断项接着往下编号。
- 「建议处置」只用四种方式，见第 4 步的表。
- 风险分三档：
  - **低**：可以恢复，且不影响功能；
  - **中**：可以恢复，但会影响某个功能，例如旧会话无法再 resume；
  - **高**：不可恢复，或会影响正在进行的工作。高风险项默认不建议，单独说明。
- 同一个原因引出的多条发现，合成一行写，例如「整套钉钉 skill 都没用过」。
- 没有问题的组写一行「无需处理」，不硬凑。

## 4. 用户勾选后执行

请用户回复要执行的编号，也可以说「A 组全做」。只执行勾选的项。执行前，再核对一遍目标仍然符合条件，例如会话记录在 24 小时内仍没有写入。

| 处置 | 做法 |
|---|---|
| trash | `trash <路径>`，一项一项执行，逐项报告结果 |
| 设置建议 | 给出要改的键和值（如 `"cleanupPeriodDays": 14`），由用户自己改；用户明确要你改时，只改这一个键，其余内容原样保留 |
| 管理器命令 | 给出命令，由用户执行，例如 `npx skills remove --global <name>`、`claude mcp remove <name>`，或在 cc-switch 里停用 |
| 仓库编辑 | 先用 `git status` 确认要改的文件没有未提交的改动；改完给出 `git diff --stat` 和要点，并列出删掉的知识点；然后只 `git add` 本次改动的文件，commit（如 `chore(<skill>): ...`）并 `git push` 到当前分支的上游；push 失败时报告原因并停下，不 force push |

改仓库外的文本文件（如 `~/.claude/CLAUDE.md`、memory）之前，先复制一份到 `mktemp -d` 新建的目录，并告诉用户备份路径。

## 5. 复扫对比

用同样的参数再跑一次扫描，报告前后对比：

- `~/.claude` 的大小；
- skill 描述总字数；
- 常驻文件的行数；
- 发现的条数。

数字没有变化的项，说明原因。
