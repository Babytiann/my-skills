# 技术文档表达

让读者快速回答：这件事解决了什么问题，关键做法是什么，为什么有用，成果体现在哪里。通过具体的判断、行动和影响呈现作者能力。

默认用中文，面向有技术背景但不了解项目细节的读者。用户给出的受众、篇幅、格式和修改范围优先。

## 先判断交付方式

| 用户需要 | 交付方式 |
|---|---|
| 根据材料起草 | 直接给可使用的成稿；必要的材料缺口放在文末简短说明 |
| 重组或改写初稿 | 保留事实，调整主线、顺序和表达；只改用户指定的范围 |
| 审稿、找表达问题 | 按影响理解的程度，指出具体位置、读者会卡在哪里、如何改；给出可替换的文字 |
| 分析文章为什么写得好 | 展示“原文做法 → 读者如何理解 → 可迁移的方法 → 适用边界” |

起草和改写时，不把取材过程、分析表格和自检清单塞进成稿。用户只要审稿时，不默认重写全文。

## 工作方法

### 1. 确定读者要带走的结论

从材料和场景判断：读者已经知道什么、最关心什么、读完应该记住哪一个变化。仅在缺失信息会明显改变主线或技术深度时追问；能从材料推断的先处理。

先尝试用一句话说清：谁原来被什么限制，关键做法改变了什么，已知结果是什么。这是选材用的判断，不是必须出现在正文里的固定句式。

### 2. 从工作记录中选出主线

按“读者需要理解什么”组织材料。一次会议、一项工具接入、一段代码通常是素材；它们共同改变的工作方式或能力，才可能成为主线。

- 找出值得讲的卡点：谁在什么任务中遇到什么限制，带来什么具体影响。
- 找出关键做法：哪项判断或设计改变了这个限制。
- 找出结果：已经发生了什么，谁的工作因此改变，有什么可展示的产物。
- 选取能解释主线的代表案例。其他材料只有在解释机制、支持结果或帮助复用时才展开。

成果明确时，可以先讲成果；场景陌生时，先用一个短场景解释问题；尚未验证的方案，先讲目标和预期机制。不要硬凑成绩或统一开头。

### 3. 安排由浅入深的阅读顺序

长文通常需要三个阅读层次，篇幅短时可合并，不必写成三个章节：

- **快速抓重点**：标题、开头和小标题让读者知道问题、核心变化和最有分量的结果。
- **理解为什么有效**：正文围绕少数关键做法，解释它们怎样改变原有约束，用案例和对照承接。
- **按需深入**：操作步骤、完整配置、长代码、更多截图放在后文或附录；决定方案能否成立的约束和关键技术细节留在正文。

用少量稳定概念串起复杂建设，避免每节换一套术语。概括必须对应实际机制，不必为了整齐凑成四步、闭环或口号。

### 4. 把每个重点讲透

逐段检查以下连接是否成立；无需把它们写成固定小标题：

> 原来哪里受限 → 关键做法改变了哪一环 → 为什么由此改善 → 有哪些已知结果或边界

使用具体的解释方式：

- **场景**：把“沟通成本高”展开为谁需要向谁解释什么、在哪一步反复。
- **同任务对照**：比较同一件事原来和现在怎样完成，点出减少的等待、转换、重复工作，或新增的能力。
- **机制**：介绍工具或模块时，先交代它负责什么，再补名称、术语和必要实现。技术名词本身不能承担因果解释。
- **案例**：选择能让读者看见输入、处理变化和结果的例子；保留使这个例子成立的条件。

如果只有做法、没有结果，解释到机制或预期为止。不能从“引入了某工具”直接写出“质量显著提升”。

### 5. 让标题、段落和图表共同指向重点

- 标题同时保留主题和具体变化；小标题尽量提示内容或结论，例如“让设计师直接修改样式配置”。避免每节只有“背景”“方案”“总结”，也避免整篇标题都写成长句。
- 段首说明这一段的重点，后文只展开同一个意思。把实现步骤与价值解释分开，减少读者自己提炼结论的负担。
- 关键技术名词首次出现时，用一句话说明它在当前问题中的作用；按读者已有知识控制解释深度。
- 比较用表格、依赖与交接用流程图、效果用示例或截图。每张图附近说明“看哪里、说明什么”；删去没有解释任务的重复素材。
- 加粗用于少数结论或关键差异。删掉加粗后，文字本身仍应能讲清重点。

### 6. 用成果与贡献完成论证

成果可以是效率、质量、覆盖范围，也可以是其他人已经能独立完成的任务、已被使用的产物。选择最能支持主线的证据，不用无关指标充数。

- 数字带上理解结论所必需的对象、基线、时间或排除项。口径不一致时不计算提升比例；缺口可以简短指出，不必把写作变成审计流程。
- 区分已发生的变化、对原因的解释、尚待验证的预期。合理机制能解释为什么可能有效，不能代替结果。
- 写清作者作出的判断和实际贡献，以及协作方承担的工作。团队成果不能自动改成个人独立完成；自动化流程中的人工验证、评审和合入也不能省成“全自动”。
- 收尾总结从案例中成立的认识、复用条件或下一步。观点应能回指前文，不额外拔高成没有依据的行业结论。

## 交付前做两次阅读

**只读开头和小标题**：能否复述主题、原有问题、关键变化，以及已知成果或当前验证阶段？如果不行，优先修开头、主线和标题。

**细读重点段落**：能否解释做法为什么有效，指出支撑结论的事实，并辨认限制？如果不行，补齐缺失的连接或降低结论强度。

这两次检查是模拟读者自检，不代表已经做过真实读者测试。审稿时优先处理价值埋得深、因果跳步、术语没有解释和主次混杂，再处理句子润色。
