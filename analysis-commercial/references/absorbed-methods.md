# 吸收的方法论

本 Skill 吸收下列规则，运行时不要再去执行对应 Skill，也不要假设仓库里的 `tools/financial_rigor.py` 或 TeamCreate 可用。出处只作声明，冲突时以本 Skill 的 S0–S4 和闸门为准。

## financial-data：两源交叉，不两源并列

出处：`financial-data` 的交叉验证，不是它的来源优先级。

- 每个关键财务数字尽量找到两个**独立 origin**，误差 `>1%` 必须标记
- 两个聚合站引用同一份财报 = 一个 origin，不能写成双源确认
- 法定披露（SEC / HKEX / 巨潮）才是 canonical；聚合站只校对抽取、单位、币种、会计口径
- 误差 `1–5%`：并列两个数字并解释口径；`>5%`：回到原文，不得直接用
- 呈现时写清来源 URL 和检索日期

## earnings-review：语气与承诺，不替代原文

出处：`earnings-review` 的一手资料习惯。

读取电话会或股东信时记录：

- 指引是上修、维持还是下修，相对一致预期的方向
- 管理层对订单、库存、定价的原话，以及是否可核对
- 承诺清单：回购、CapEx、产品节奏、去库存。下一次检查是否兑现
- GAAP 与 Non-GAAP 是否被用来遮盖现金
- 若只有汇总站没有原文：标注“非原始财报”，并降低附注权重

这些记录进入账本，不在本 Skill 里重写一份完整财报研报。

## quality-screen：问题清单，不是波段否决线

出处：`quality-screen` 的检查维度。**不要**把 7 条长期排除阈值当成 1–6 个月波段的硬否决。周期反转单常常 ROE 低、某几年现金流为负。

当作风险旗来问：

- 利润能否收成现金（经营现金流 / 净利润）
- 利息覆盖是否危险
- 股本是否在非并购情况下明显膨胀
- 治理、关联交易、审计师更换、大股东减持
- 商誉和一次性项目是否撑起利润

旗升起时写入账本和报告风险段。只有当这些问题在持有期内会破坏退出或缺口假设时，才把动作降为 `不交易`。

## news-pulse：只回收时间线，不回收买卖

盘中 10 分钟归因让渡给 `news-pulse`。若当前问题其实是“刚才为什么动”，应让用户改走那边。

若在本 Skill 全量建档里需要事件时间线：自己按 S0–S2 建 `timeline.json`，不要启动 TeamCreate。新闻只当 S4 线索。

## 明确不吸收

- `investment-research` 的十年买入论文
- `quality-screen` 的 10 年 ROE < 8% 等排除阈值
- 任何付费终端的独家字段
